# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

NoThrow is a lightweight, **dependency-free** Result pattern library for .NET, published as the NuGet package `NoThrow`. Keep the core package free of external dependencies.

## Commands

The solution uses the new `.slnx` format; `global.json` pins the .NET 10 SDK line (`rollForward: latestFeature`).

```sh
dotnet build                                   # builds src and tests (net8.0 + net10.0)
dotnet test                                    # runs all xUnit tests on net8.0 and net10.0 (needs both runtimes)
dotnet test -f net10.0                         # without the .NET 8 runtime installed
dotnet test --filter "FullyQualifiedName~ResultTests"                          # one test class
dotnet test --filter "FullyQualifiedName=NoThrow.Tests.ResultTests.Bind_RunsNextOnlyOnSuccess"  # one test
dotnet pack src/NoThrow -c Release            # produces .nupkg + .snupkg
dotnet run -c Release --project benchmarks/NoThrow.Benchmarks -- --filter "*"  # BenchmarkDotNet (add --job short for a quick run)
```

`benchmarks/NoThrow.Benchmarks` is the only project allowed to take a third-party dependency (BenchmarkDotNet); it is not packed and not run by `dotnet test`.

There is no separate linter: `TreatWarningsAsErrors` is on for every project, and `GenerateDocumentationFile` is on for `src/`, so **every public member needs an XML doc comment** or the build fails (CS1591). `EnforceCodeStyleInBuild` (root props) makes the `.editorconfig` rules at `warning` fail the build: formatting (IDE0055), file-scoped namespaces, using placement, accessibility modifiers, `readonly` fields, naming (`_camelCase` private fields, PascalCase constants/static readonly), plus braces (IDE0011) and unused usings (IDE0005) in `src/` only — tests and benchmarks mirror the README's brace-less early returns, and IDE0005 needs `GenerateDocumentationFile`. Some rules are honored by the build only through `dotnet_diagnostic.<id>.severity`, which is why the enforced ones are listed by id; `this.`/predefined-type preferences stay IDE suggestions because the command-line build does not report them. `src/` also runs `AnalysisLevel=latest-recommended`; its three deliberate exceptions (CA1716 on `Error`, CA1000 on `Result<TValue>.Failure`, CA2208 in `Error.ValidateType`) are `[SuppressMessage]`s with a justification at the declaration — add new exceptions the same way, never project-wide.

CI (`.github/workflows/ci.yml`, GitHub Actions) runs restore → build (Release) → test on both TFMs → pack on every push to `main` and every pull request, with `permissions: contents: read` and third-party actions pinned by commit SHA (version in a comment; bump both together).

## Build configuration

- `Directory.Build.props` (root) — applies to all projects: `Nullable`, `ImplicitUsings`, `TreatWarningsAsErrors`.
- `src/Directory.Build.props` — imports the root one and adds packaging metadata shared by **every package under `src/`**: target frameworks (`net8.0;net10.0`, supported LTS only), `VersionPrefix`, license, tags, symbols, `IsAotCompatible` (no reflection — the trim/AOT analyzers enforce it), and packs the root `README.md` as the package readme. It also enables SourceLink metadata (`PublishRepositoryUrl`, `EmbedUntrackedSources`; SourceLink ships with the SDK), `ContinuousIntegrationBuild` when `CI=true` (normalized PDB paths), and `EnablePackageValidation`. API-break detection uses the SDK's package validation, **not** `PublicApiAnalyzers`, which would be a third-party dependency under `src/`. It has blind spots: sealing an override (as `Error.ToString()` was) passes validation, even in strict mode, yet types compiled against the old version that override it fail with `TypeLoadException` — such breaks must be declared in the CHANGELOG by hand. Individual `.csproj` files only set `PackageId` and `Description`. New packages (e.g. integrations) go under `src/` and inherit this.
- Tests target `net8.0;net10.0`, the same TFMs as the package, and compile with each TFM's default C# version (C# 12 on `net8.0`).

## GitHub repository settings

The repository is public and open to outside contributions. Settings that live on GitHub, not in the repo:

- **Rulesets on `main`**: `main: CI and history` (no bypass) blocks deletion and force-pushes, requires linear history and the `build` status check from `ci.yml` with the branch up to date. **Renaming the `build` job in `ci.yml` blocks every merge** until the ruleset's required check is renamed too. `main: review` requires a pull request with 1 approval, code-owner review (`.github/CODEOWNERS`), stale-review dismissal, approval of the last push and resolved conversations, squash merge only; the repository admin can bypass it **only through a pull request** (to merge their own PRs without approval), never by pushing directly. So every change, the maintainer's included, goes branch → PR → green CI → squash merge.
- **Ruleset `release tags`** (`refs/tags/v*`): only the repository admin can create, move or delete version tags, since pushing one publishes to nuget.org.
- Merging: squash only, PR title/body become the commit (so PR titles follow Conventional Commits), auto-merge and "update branch" enabled, head branches deleted on merge.
- Security: private vulnerability reporting (the channel `SECURITY.md` points to), Dependabot alerts and security updates, secret scanning with push protection, CodeQL default setup (C# and Actions). Outside contributors' workflow runs need approval.
- Community files: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), `SECURITY.md`, `SUPPORT.md`, issue forms and PR template under `.github/`. Questions go to Discussions; blank issues are disabled. Keep these in sync with the conventions below when they change.

## Release checklist

Publishing is done by `.github/workflows/release.yml` when a `v*` tag is pushed. Job `publish` (`contents: read`, `id-token: write`) first checks that `CHANGELOG.md` has a section for the version — **before** anything is pushed, since a published version can only be unlisted, never deleted — then tests, packs with the tag as the version (`v0.1.0` → `0.1.0`) and pushes to nuget.org through Trusted Publishing (OIDC via `NuGet/login`, user `eovinicius`; no API key is stored). The nuget.org policy must match owner `eovinicius`, repository `nothrow`, workflow `release.yml` — renaming the file breaks publishing. Job `github-release` (`contents: write`, only after `publish` succeeds) creates the GitHub Release with that CHANGELOG section as its notes (`--prerelease` when the version has a `-` suffix). Both use `.github/scripts/changelog-section.sh <version>`, which prints a version's section and exits 1 when it is missing or empty.

`CHANGELOG.md` follows Keep a Changelog: user-visible changes go under `## [Unreleased]` in the PR that makes them (`Added`/`Changed`/`Fixed`/`Removed`, plus `Breaking`); headings carry no link references, so the script can extract them. The package's `PackageReleaseNotes` links to the CHANGELOG.

1. Check that CI is green on the commit being released.
2. In one PR: bump `VersionPrefix` to the version being released, and rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD` with a fresh empty `## [Unreleased]` above it. Tag the merged commit on `main`.
3. `git tag vX.Y.Z && git push origin vX.Y.Z`, then follow the Release run (NuGet, then the GitHub Release).
4. After the first version is published, set `PackageValidationBaselineVersion` to it so `dotnet pack` fails on undeclared API breaks; keep it at the latest published version afterwards.

## Architecture

All types live in the `NoThrow` namespace in `src/NoThrow/`:

- `Error` — a non-sealed `record (Code, Message, ErrorType)` with factory methods per `ErrorType`. `Error.None` marks success; `Error.NullValue` (an `ErrorType.Failure`) is produced when `null` is converted into a `Result<T>`. It's non-sealed so `ValidationError` can derive from it, and applications may derive their own error records too — it cannot be sealed against them anyway, since a non-sealed record's copy constructor must be `public`/`protected` (CS8878). `Code`/`Message`/`Type` are declared explicitly over `readonly` fields so both the constructor and `with` validate them (no `field` keyword: `net8.0` compiles with C# 12): `null` strings are rejected, while empty strings stay legal because `Error.None` uses them; `Type` must be a declared `ErrorType` member or `>= 1000` (`ValidateType`, a range check `Failure..Conflict` — `Constructor_AcceptsEveryDefinedType` fails if a member is added without widening it). The `init` accessors of `Code`/`Type` also consult `private protected virtual HasFixedCodeAndType` (`true` only in `ValidationError`) and reject a *different* value, so `with` cannot break `ValidationError`'s code/type while still accepting the same value (needed by deserializers that set every property). `Is(other)` compares `Code` (ordinal) and `Type` only; `==` still compares every member. `ToString()` is `sealed override` (so derived records don't synthesize their own and leak their members): it prints `TypeName { … }` from `private protected virtual AppendSafeMembers` (`Code`, `Type`; `ValidationError` adds field names), and `PrintMembers` (kept for the record contract) delegates to it. Never `Message`.
- `ValidationError` — sealed record deriving from `Error` with fixed code `Validation.Failed`; aggregates per-field errors where each inner `Error.Code` is the field name. Requires at least one error, rejects `null` and `Error.None` items, flattens nested `ValidationError`s (one level suffices, since each is flat by construction), and keeps the copy in a private array. Overrides `Equals`/`GetHashCode` (allocation-free) so equality covers the list contents, and `AppendSafeMembers` so `ToString` lists only field names (its explicit `PrintMembers` override stops the compiler from synthesizing one that lists every property).
- `ErrorType` — the category; the doc comment anticipates integrations (e.g. HTTP) mapping it to their own vocabulary such as status codes. Values `>= 1000` are reserved for application-defined categories (declared as `const ErrorType X = (ErrorType)1000;`); new built-in members are only added below 1000 and integrations treat unknown values as `Failure`.
- `Result` / `Result<TValue>` (both in `Result.cs`) — `Result<TValue>` is `sealed` and derives from `Result`, whose constructor is `private protected`: only the library can create results, so the invariants can't be bypassed by subclassing. Key invariants enforced by the constructor: success ⇔ `Error` is `Error.None` **by reference** (violations throw `InvalidOperationException`; a `null` error throws `ArgumentNullException`). `Result.Success<T>(null)` throws — `Create` is the null-tolerant path. `Result.Success()` returns a shared cached instance. `Value` throws on failure (message includes the error code); `ValueOrDefault` never throws; `TryGetValue(out value, out error)` unwraps both; `TryGetError(out error)` is the one-line unwrap for a valueless `Result` (`true` on failure, `Error.None` on success). `Result<TValue>` hides the inherited `Failure(Error)` with a `new static` one returning `Result<TValue>` — inside `Result<TValue>`, an unqualified `Failure(error)` now binds to it. `Result.Combine(params Result[])` returns the first non-validation failure, or merges all validation failures into one `ValidationError` — except a lone failing `ValidationError`, returned as the same instance so its custom message survives.
- `ResultJsonConverter` — makes `System.Text.Json` reject `Result`/`Result<T>` in both directions with an actionable `NotSupportedException`; applied by `[JsonConverter]` on both types (one non-generic `JsonConverter<Result>` with `CanConvert` covering derived types — no `MakeGenericType`, so AOT-safe; STJ accepts it for `Result<T>`). It is **public** (`[EditorBrowsable(Never)]`) on purpose: with an `internal` converter the STJ source generator in the consumer's assembly skips the type (SYSLIB1030). `Error` carries `[JsonPolymorphic(FallBackToNearestAncestor)]` + `[JsonDerivedType(typeof(ValidationError))]` (no discriminator), so an `Error`-typed `ValidationError` writes its `Errors` and application-derived errors write as `Error`. `TestJsonContext` in the tests exercises the source-generated path. STJ is part of the shared framework: no package dependency.
- `ResultExtensions` — combinators that must return the receiver's own type (`Ensure`, `Tap`, `TapError`, `MapError`). They're extensions, not instance methods on `Result`, because an instance method there would return a plain `Result` when called on a `Result<T>` and lose the value. It also holds `[Obsolete(error: true)]` + `[EditorBrowsable(Never)]` overloads of `Tap`/`TapError` taking `Func<…, Task>`: they exist only so an `async` delegate binds to them and fails to compile, instead of binding to the `Action` overload as `async void`. Don't remove them.
- `ResultAsyncExtensions` — `*Async` versions of the composition API, on a result (async delegate) and on `Task<Result>` / `Task<Result<T>>` (sync or async delegate; `MapErrorAsync` is sync-only). `TapAsync`/`TapErrorAsync` take `Func<…, Task>` and await it. Always `ConfigureAwait(false)`; `Task` only, no `ValueTask`. Exceptions follow TAP: every method is a non-`async` wrapper that `ThrowIfNull`s each argument (receiver, task, delegates, `error`) and returns `Core(...)`, a `static async` local function with the body — so a `null` argument throws from the call, and a delegate's exception (even a synchronous throw before it returns a task) always faults the returned task. Keep this shape for new overloads; `ResultAsyncExtensionsTests` covers every overload's `null` arguments. The cost is one `Task` (72 B) per call on the success path of the six methods on a `Result`/`Result<T>` that used to pass the delegate's task through. Sync-vs-async delegate overloads rely on C#'s "more specific" / better-conversion tie-break (a delegate with a return type beats a `void` one for an `async` lambda), covered by `ResultAsyncExtensionsTests`.

Design decisions to preserve:

- Implicit conversions: `Error → Result`, `Error → Result<T>`, `T → Result<T>`. The `T → Result<T>` parameter is annotated non-nullable on purpose, so converting a maybe-`null` value warns (CS8604) and steers callers to `Result.Create(value, error)`; a `null` that still arrives yields `Error.NullValue` (via `Result.Create`). C# disallows user-defined conversions from interfaces, so when the expression's static type is an interface callers must use `Result.Success(value)`.
- `Map` goes through `Create`, so a `null` mapper output becomes a `NullValue` failure.
- Argument validation is eager everywhere: sync combinators and `Result.Create(value, errorIfNull)` `ThrowIfNull` every argument on every call, even on the branch that would not use it, so a mistake shows up the first time the code runs rather than on the first failure.
- Composition API is `Match`, `Map`, `Bind`, `Ensure`, `Tap`, `TapError`, `MapError` plus their `*Async` counterparts; failures propagate by re-wrapping `Error` in the target result type, and combinators whose target type the receiver already is (including `Result<T>.Bind` to a plain `Result`) return the same instance (no allocation).
- `ToString()` never prints the value (`Success` / `Failure(Code)`) so logs can't leak it; `Result<T>` shows the value only through `[DebuggerDisplay]`. Likewise `Error.ToString()` never prints `Message`, and `ValidationError.ToString()` prints only field names. That guarantee is about `ToString()`: destructuring loggers and reflection-based serializers read public properties, which is why results reject STJ serialization and the README says not to destructure them.

## Conventions

- Tests: xUnit, `Assert.*` only (no assertion library), named `Member_ExpectedBehavior` (e.g. `Failure_WithErrorNone_Throws`), one test class per public type (`ResultTests`, `ResultOfTValueTests`, `ErrorTests`, `ResultExtensionsTests`, `ResultAsyncExtensionsTests`), plus `ReadmeTests` for the README and `TestJsonContext` for source-generated JSON.
- When changing public behavior, keep `README.md` in sync — it's shipped as the NuGet package readme. That includes the **Pitfalls** and **Testing** sections, not just the API walkthrough. The README leads with the early-return style (`if (x.IsFailure) return x.Error;`, `TryGetValue`, `TryGetError`, `Result.Combine`); fluent combinators are presented as optional. Its snippets must compile on `net8.0` with nullable enabled, and `ReadmeTests` enforces it in CI: it extracts every ` ```csharp ` block (other C# fences such as ` ```cs ` fail the test, since they would be skipped), parses each as a C# script with Roslyn (`Microsoft.CodeAnalysis.CSharp`, a test-only dependency), puts type declarations at the top level and members/statements in a `SnippetN : SnippetContext` class, and compiles everything as C# 12 with nullable enabled, failing on errors and `CS86xx` warnings; `#line` maps diagnostics to README lines. Names a snippet assumes but does not declare are stubbed in its `Stubs` string — when a snippet needs a new one, add it there; when a snippet is wrong, fix the README.
